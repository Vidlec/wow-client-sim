# AddonSim: 60 frames a second (2026-11-22)

A copy of the code before these changes is in `C:\Users\vidle\AddonSim-backups\before-60fps-2026-11-22` (no cache, no
saves).

## Before and after

The simulator's work per frame (input, tick, scene), standalone, mouse moving each frame:

| Screen | Before (30 Hz clock, whole scene as JSON) | After (60 Hz, changes only) |
| --- | --- | --- |
| World | 12.0 ms avg, p95 24 ms, 48 KB a frame | 1.5 ms avg, p95 3 ms, 0.4 KB |
| World map open | 21.3 ms avg, p95 42 ms, 124 KB a frame | 6.4 ms avg, p95 15 ms, 2 KB |

Live (server and page, headless Chrome on the RTX 4080, world map open, the mouse moving every display frame): 60-70
frames a second reach the page while the scene changes, the GPU draws one in 0.6-0.8 ms (700 quads), a mouse move is
on screen 9 ms later (p50; p95 20 ms). The clock was capped at 30 before.

## What changed

**The clock and the transport** (`server.py`, `scenestream.py`)
- The clock runs at `fps` from config.json, 60 by default.
- One request a frame: the page's input since the last frame, the tick, the scene. Input no longer waits for the
  simulator on its own (moves after moves count once), so it never holds a frame back.
- The scene is pushed over a WebSocket (standard library, no dependency): a whole scene when a page joins, then only
  what changed. A page that falls behind is sent the whole scene again. Without the socket the page polls
  `/api/scene` as before (it answers with whole scenes).
- `/api/state` passes the simulator's JSON through as written (it was read and written again, 200 KB, while holding
  the simulator).

**The simulator** (`lua/`)
- `stream.lua`: what changed since the last frame: items compared with copies of what was sent, the order only when it
  changed.
- Layout kept between frames: a colour, an alpha, the mouse over a button, shown or hidden no longer throw away every
  rectangle (`sim.touchVisual`); a change to one object's anchors, size or text throws away its rectangle and those
  worked out from it (`W.touchLayoutOf`, dependencies recorded as rectangles are computed). Setters given what is
  already there do nothing (Blizzard's raid manager set the same text every frame).
- Scene export: the draw order from a walk down the shown frames (597 of 13 589), not a scan of all of them; no
  closures or tables made per frame; regions sorted on one key, the order kept while it stands; alpha and clip worked
  out once per frame; font lookups and keys kept.
- `scenarios/scene-stream.lua` checks it: the page's scene put together from the frames is the whole export, every
  frame (world, map, joining midway, OneMoreQuest's log), and the rectangles kept are the ones worked out afresh.

**The page** (`web/`)
- `gl-renderer.js`: WebGL2. Each item a few quads in one buffer, drawn in order in as few calls as the textures allow;
  vertex colour, alpha, greying, masks (screen-fixed, as the minimap's), clipping and ADD/MOD blending in the shader;
  nine-slices, tiling, rotation, moved corners (SetVertexOffset: the corners move, as in the game, rather than a cut),
  backdrops, lines. Text laid out once per string (the game's fonts, colour codes, inline icons, shadow, outline)
  and kept as a texture. MSAA on.
- Drawn at the browser's next frame after a change, once however many changes came.
- `?renderer=dom` draws with the page's elements as before; the picture pages still do by default
  (`&renderer=gl` draws a shot with the GPU). If the GPU's context is lost the page falls back to its elements.
- The status bar shows the clock (frames a second, time a frame, the worst split into code, list and send) and the
  page's draws a second with the renderer's time.

# Later the same day: faster tests, holes filled, Edit Mode

## Testing

| | Before | After |
| --- | --- | --- |
| Whole suite (`python play.py`, 20 processors) | 77 s | 20 s |
| A boot | 4.5 s | 2.0 s (6 s the first time, filling the cache) |
| `quest-pages` (664 quest pages) | 49 s | 4 parts side by side, 17 s each |

- `lua/bootcache.lua`: the game's tables, atlases, TOCs (QuestieDB's is 19 MB), XML trees and the compiled Lua of the
  interface and addons kept in `cache/boot` as bytecode, found by each file's write time and size.
- Faster code on every run: `issecure` judges each function once (it walked and string-matched the whole stack on
  every call: 10% of a scenario's time); `sim.call` makes no table or closure a call; the OnUpdate list is sorted only
  when it changes; TOC lines trimmed in one pass (quadratic before); the API docs compiled once, not four times; XML
  tags scanned with finds; base64 decoded through LuaJIT's FFI (QuestieDB decodes its database at login); DB2 CSV
  lines split only to the last column wanted.
- `play.py`: each report's time, the five slowest, the slowest started first next time (`scenarios/.timings.json`),
  and `--@shards N` with `forShard(list)` for a long scenario.

# Then: measured in the real client

`/asrec probe` (the recorder) measures the client where its code says nothing; `tools/probe-sim.lua` compares. What
it showed, now as the client does:

- **OnShow and OnHide run the children first** (deepest first, then the frame). The sim ran the parent first: the
  guild window's error came from that (its list fills itself in its own OnShow, which the window's then reads).
  With it and `strlenutf8` (a stand-in that answered nothing) the guild window opens with no error.
- **Raise and Lower leave the frame level alone**: they order a frame among the others of its level. Frame level
  comes first (Edit Mode's dialogs at 100 over its window). This morning's change (Raise lifting levels) is undone.
- **SetFrameLevel moves the children by as much** (5 -> 50: children at 6 and 20 go to 51 and 65).
- Achievements: the client lists and counts set "a" (the 0x08000000 copies), finds both by id, and leaves tracking
  achievements (0x100000) out: 111 counted, as there. Categories by order then id, "Do Not Display" among them.
  The legacy track's data as the client gives it ("Legacy Track", 90 levels, textureKit "storm"...).
- `GetNumClasses` is 9; empty slot pictures are file ids (the ammo slot the ranged one, bags and profession slots
  the generic one); `UnitArmor` gives 4 values, `UnitAttackSpeed` 3, `GetHealthRegen` 2; a missing achievement gives
  no values at all.
- Matched already: ClearAttribute runs no OnAttributeChanged, ClearText leaves nil, GetFontInfo's shape, no encounter
  journal tiers, a new child's level (its parent's + 1).
- `AbbreviateLargeNumbers` and `AbbreviateNumbers` (stand-ins before).
