# 2026-11-24: the character window and the spellbook

Reported: the spellbook showed nothing; the character window had no stats, its tabs on the side did nothing, and its
title read "Level 30 |cMage".

- **A frame's mouse scripts take the mouse** (`lua/widgets.lua`, `lua/xmlui.lua`): a frame given OnEnter, OnLeave,
  OnMouseDown or OnMouseUp (in its XML, or by SetScript or HookScript) gets the mouse, as in the client, unless it
  said otherwise (EnableMouse). The character window's side tabs (LargeSideTabButtonTemplate, frames with only those
  scripts) are clickable now.
- **Two points on one edge** (`lua/widgets.lua`): where two anchors set the same edge, the one first in the client's
  order of points wins (TOPLEFT, TOP, TOPRIGHT, LEFT, CENTER, RIGHT, BOTTOMLEFT, BOTTOM, BOTTOMRIGHT), not the one set
  last. The character window's right pane is anchored TOPLEFT to the paper doll's right edge and BOTTOMLEFT to its
  left one: it lay over the paper doll, with the stats under the model.
- **C_ColorUtil** (`lua/colorutil.lua`): the colour codes ColorMixin's GenerateHexColor and WrapTextInColorCode are
  made of, and the RGB/HSV/HSL conversions. Every class colour's colorStr was "" (the title's "|cMage").
- **The spellbook** (`lua/spellbook.lua`, `C_SpellBook` in `lua/game.lua`): General (Attack, the race's abilities,
  the class's Shoot) and a tab for each of the class's schools, every rank trained by the character's level, from the
  game's tables (SkillLine, SkillLineAbility, SpellLevels, SpellMisc, Talent, now fetched for Forever). Left out:
  talents and their effects, runes (Engraving), spells the client never shows. Lower ranks are marked (the book's
  "hide lower ranks"), passives too. `GetClassSkillLineInfo` gives the General tab its class icon.
- `C_ActionBar.FindSpellActionButtons` answers nil when no button holds the spell (the game's code tests for it; its
  documentation says a table) and searches the set of bars asked for; `C_GamepadUI.GetFirstGamepadActionStorageSlotIndex`
  is real (the spellbook asks it for every spell).
- **Pictures wait for their art** (`src/ui/engine/picture.ts`, `textures.ts`, `atlas.ts`): headless Chrome's clock
  is virtual, and the picture page said "ready" after eight redraws whether its art had arrived or not: busy scenes
  (the character window) lost atlases and icons at random. It now holds the clock with a short request (`/hold`,
  in the SDK's picture server and the app's) until every atlas and picture asked for has arrived.
- `scenarios/game-windows.lua` checks all of it; `lua/tests/colorutil.lua` the colour codes.

  the game's code nor its string table has (an addon's own probe, `EUI_CLIENT_BLOCKED`) reads nil unlisted; a
  documented enumeration's unknown value is nil, as in the client (`Enum.ItemWeaponSubclass.Bow`), not a made-up number.
- Screenshots: Chrome without its crash reporter, and its profile removed best-effort: the reporter's process held it
  on Windows, and the EBUSY failed a finished picture (the intermittent `a picture of a frame` failure).

- Stand-ins: RequestRaidInfo (UPDATE_INSTANCE_INFO next frame), GetNumSavedInstances, C_CurrencyInfo.GetCurrencyListSize,

## The Forever client's answers, frames of one level, EllesmereUI's settings pages

- **The recorder's probe** (`/asrec probe`, loaded at boot as `sim.recordedProbe`) settles what the Forever client
  answers: one specialization per class (from the recording, the class name without one), paladin auras as shapeshift
  forms (their highest known rank), the 41 active game rules and `Enum.GameRule`'s values, cooldowns drawing their edge
  by default at an edge scale of √2 (no `IsHidingCountdownNumbers`), `IsDesaturated` true for any amount,
  `GetFillStyle` a number, `CanInspect` for any player, `GetRealmID` 0, Encounter Journal tier 0,
  `FindSpellOverrideByID` the spell itself, `GetInspectItemLevel("player")` 0, and an animated alpha from `GetAlpha`.
  The recorder now also records every class's specializations and the client's enumerations (`/asrec api`).
- **Frames of one level are drawn together**: frames sharing strata, level and raise have their regions sorted by
  layer as one, as the client draws a level. A frame at its parent's level (EllesmereUI's game menu insets) puts its
  background under the button's text, not over it.
- **A child keeps its own level**, at or below its parent's too: only children drawn at their parent's level
  (`useParentLevel`) follow it. EllesmereUI's minimap indicators hold a black backdrop one level below the button; it
  had been lifted over the icon, so the tracking, calendar, friends and EllesmereUI buttons looked dim.
- **Hairlines on a smaller canvas**: a straight quad thinner than a canvas pixel (a 1-pixel border of a 4K game drawn
  smaller) is drawn a pixel wide and as faint as it is thin, so borders no longer break where they fall between pixels.
- **`debugstack` with each file's whole path**: LuaJIT cut source names past 60 characters
  (`...ddOns/EllesmereUIOptions/...`), so EllesmereUI, which accepts a settings page only from its options addon found
  by `debugstack(2, 1, 0)`, dropped the Cooldown Manager's page and its sidebar entry did nothing.
- `C_AddOns.IsAddOnLoaded` answers "loaded or loading" first while an addon's files run, as the client does.
- **The client's enumerations and constants** (`/asrec api`, `api.enums` and `api.constantTables`) are laid over those
  the documentation makes (`apisurface.applyEnums`, right after `docs.load`): the client's values win, and what the
  documentation leaves out (`Enum.GameRule`) is the client's number, not a made-up one.
- **Specializations of every class** from the probe (`GetSpecializationInfoForClassID`: a global in this client, the
  namespace has none; the recorder looked in the namespace and recorded nothing), answering not recommended and not
  allowed, as the client does.
- **Recorded constants, numbers only**: the recorder had saved every number and true/false in `_G` after all addons
  loaded, `g_middleClassLoaded = true` among them; set before the game's code ran, middleclass skipped itself and
  every tutorial failed. The sim now takes numbers only, and the recorder saves the numbers as it loads, before the
  other addons add theirs.
- **Addons loaded on demand wait**, as in the client: listed with the rest, an addon with `LoadOnDemand: 1` is not
  loaded at login (nor for an addon naming it an optional dependency); code loads it (`C_AddOns.LoadAddOn`) or an addon
  loaded at login needs it. EllesmereUIOptions loaded with the rest came before QoL, Quest Tracker, Quickdraw, Raid
  Frames, Resource Bars and Unit Frames, whose namespaces their pages need: six sidebar entries did nothing
  (AddonCompat `eui-sidebar.lua` clicks every entry).
- **A slider runs up and down unless it says otherwise** (`W.orientationOf`): the game's horizontal templates name
  HORIZONTAL, its scroll bar template names nothing. Taken as HORIZONTAL, a scroll bar's thumb moved sideways in its
  16 pixels and seemed stuck (DungeonJournal's lists; `scrollbar-thumb.lua`). A status bar stays HORIZONTAL.

- Server: the catalog carries `richTitle`, `category`, `group` and `iconTexture` (`groupAddons`, tested).
- Categories stand out: each a panel of its own under a gold heading band (the game's header gold, unless the TOC

## Faster frames (a dragged window: 45 to about 70 frames a second)

- **Rectangles kept**: setters that change no place asked for a redraw (`sim.touchVisual`) instead of a new layout
  (`sim.touch`, which throws every rectangle away): making a texture or a frame, justification, draw layer, frame
  level, a bar's or slider's value and range, its texture and fill direction, clipping; word wrap and max lines throw
  away only their own string's rectangle and what hangs from it; SetScale and SetIgnoreParentScale only when they
  change. With EllesmereUI the layout was thrown away 9.5 times a frame, now about once in two; computeRect went
  from a third of the scene's export to 5%.
- **Visibility kept** (`W.touchVisibility`): IsVisible is worked out once while nothing is shown, hidden or
  re-parented; walking up the parents was half of the tick (the clock asks it of every frame with an OnUpdate).
- **The garbage collector between frames** (`lua/idlegc.lua`): after a frame's answer it works for up to 2 ms while
  the server has not asked for the next one, and is stopped during frames; any other request has it as usual, and
  so do frames when garbage grows faster than the idle time clears it.
- **The frames' averages** in `simulatorPerf` (input, tick, export, encode, the collector's idle time), timed with the
  fine clock (os.clock counts whole milliseconds on Windows).
- The game clock can be set to 120 (Settings, Game clock): a frame takes about 4 ms when nothing moves.

## Kept scene items, and a dragged window at 110 to 120 frames a second

- **Kept items** (`lua/scene.lua`): a region's items from the last export are used again while everything they were
  made from stands (its visual version, rectangle, scale, alpha, clip, masks, font objects, flattening, the edit
  cursor, the screen's height); its backdrop too. Animated objects, timer bars, lines, message frames, units and
  cooldowns are made every time. An idle frame of the live game makes 4 regions' items and keeps 939; the stream
  does not compare a kept item (the same table is the same item).
- **Per-object change marks**: `sim.touchVisual(object)`, `sim.touch(object)` and `touchLayoutOf(object)` move the
  object's visual version on (every setter in `lua/widgets.lua` passes its object); font objects' changes move
  `fonts.version`. Setters that set another region's state (SetNormalTexture and kin, SetThumbTexture,
  SetStatusBarTexture) mark that region.
- **Checked**: `ADDONSIM_CHECK_SCENE=1` exports after every tick of the game's clock, makes every export a second
  time without kept items and reports any difference as an error (and the stream compares kept items all the same).
  The suites pass with it.
- **OnSizeChanged and scroll ranges** told only for frames whose rectangles changed since the last look (every
  watcher after a whole new layout), sizes compared past rounding (a moved frame's width came back 663.9999999999999:
  sixty to eighty OnSizeChanged a step while a window was dragged, 4 ms a tick).
- **The drawing order** is sorted again only when it changed: SetFrameLevel and SetFrameStrata to what they are,
  frames shown, hidden or made under a hidden parent no longer ask for it.
- **More setters that move nothing** ask for a redraw only (mouse down and up, strata, Raise and Lower, a line's
  ends, orientation, enabled, fill style); text spacing, scale and height lay out only their own string.
- **Full speed on Windows** (`lua/fullspeed.lua`): the host asks out of power throttling (EcoQoS), which slowed it as
  a background process between frames.
- `ADDONSIM_PROFILE_FILE=<path>`: a sampling profile of the server's simulator, written every 4 s
  (`lua/hostprofile.lua`); `simulatorPerf.average` gains the tick's parts and the size watchers' counts.

## Moves, and the scene stream in Rust

- **Moves** (`lua/scene.lua`): a kept item whose shape stands (state, size, scale, alpha, where its clip and masks lie
  from it) but whose place changed is given its new boxes in place instead of being made again; the stream sends it
  as a move, its key and boxes (`mv`), and the page puts them on the item it holds (src/ui/engine/scene.ts). A dragged
  window's 280 items are no longer made, compared and sent whole at every step.
- **The native core** (`native/`, Rust, `bun run native` to build): the scene stream's item store. Lua packs each new
  or changed item into bytes (`lua/pack.lua`, an FFI buffer: no garbage), the store keeps what the page holds,
  compares and writes binary frames (new keys, the order, changed items, moves); a page that joins gets the whole
  scene from it. Loaded by LuaJIT's FFI (`lua/native.lua`); without it (not built, `ADDONSIM_NATIVE=0`) the stream is
  the JSON one as before.
- **Binary frames end to end**: the host writes a frame's JSON header line ending in `"bin":N` and N bytes after it
  (stdout in binary mode on Windows); the server reads them (`src/server/frameReader.ts`) and sends each page one
  binary WebSocket message; the page reads it into the same frame it applies (`src/ui/engine/binaryFrame.ts`). The
  old HTTP poll and tools still get JSON. Checked: the scene a page builds from binary frames, the binary whole scene
  and the JSON one are the same, item for item, with the whole interface and EllesmereUI.
- A dragged window in the live game: 121 frames a second (the clock's own), a frame 5 to 6 ms on the server; the
  page now draws 110 to 118 of them a second (80 before).

## The scene walked in Rust

- **The walk** (`native/src/graph.rs`): the export's walk over every shown frame and region moved to Rust, rules
  ported one for one from `lua/scene.lua`: the frames by level group, their regions sorted together (layer, text over
  textures, sublevel, rank, art order, id), which show (a button's state textures, highlights), each one's alpha
  (animated ones too) and clip, and whether its items stand, only moved (their new boxes worked out there, rounded as
  `toBox` rounds) or must be made again. Lua makes only those (`scene.buildRegion`, `buildBefore`, `buildAfter`: the
  export's own builders, shared with it), packs them and hands them back; the store puts the frame together.
- **The mirror** (`lua/scenesync.lua`): told only what changed since the last frame: the objects whose setters said so
  (`W.onChanged`), the rectangles thrown away for frames in sight and their regions (`W.onRectDropped`), the drawing
  order when it changed (frames come into sight told whole), and each frame the frame under the mouse, the one
  pressed, the focus, the font objects' version, the screen's height and the animations playing.
- **Checked**: `ADDONSIM_CHECK_SCENE=1` also walks after every tick and compares the scene the walk made (read back
  from the store, `lua/unpack.lua`) with the one Lua exports, item by item: all three suites (AddonSim 34, WowAddons
  41, EllesmereUI 14) pass with it. It found one real fault on the way: items let go while their region was out of
  sight were still counted as kept when it came back (now: kept only while the store holds them).
- **Fast paths in the store and the walk**: everything indexed by id in vectors, memos stamped with the walk's
  number, stamps in reused buffers; the native library loaded from a copy in `cache/`, so `bun run native` works while
  the server runs. Clicks and the edit focus no longer throw the whole layout away.
- Live, with EllesmereUI and 26 more addons: an idle frame 0.6 ms of Lua (walk 0.1 ms in Rust), a dragged window
  2.3 to 2.9 ms (walk 0.2 ms; the rest is Lua working out the moved rectangles, about 1.2 ms, and the tick).
  `simulatorPerf.walk` reports the walk's parts and its kept, moved and made regions a frame.

## The layout in Rust

- **The walk lays the scene out itself** (`native/src/layout.rs`): each object's rectangle from its anchors, size,
  scale, parent and content, ported rule for rule from `lua/widgets.lua` (`computeRect`, `getNaturalSize`,
  `getEffectiveScale`): anchor ranks, a scroll frame's child, anchorless textures and texts, an atlas's size, regions
  that collapse while hidden, clamping to the screen. Rectangles are kept until what they come from changes; each
  object records whose rectangles were worked out from its own, so a dragged window is one anchor told and its
  dependents laid out again in Rust. A text's size is measured by the Lua side (`lua/fonts.lua`, called back) and kept
  per text and font objects' version.
- **The mirror** is told anchors (`sg_points`), sizes, an atlas's size, scroll offsets and the layout flags with each
  object, and the screen's width; it is no longer told rectangles (`W.onRectDropped` is gone). Scroll frames now say
  when their offset changes (`SetVerticalScroll`, `SetHorizontalScroll`, the world map's pan).
- What addons ask (`GetRect`, `GetWidth`, `GetPoint` and the like) is still answered by the Lua layout, unchanged.
- **Checked**: `ADDONSIM_CHECK_SCENE=1` also compares every shown frame's and region's rectangle in both layouts after
  every tick (`scenesync.checkLayout`); all three suites pass with it.
- Live, dragging the character window with EllesmereUI and 26 more addons: a frame 1.1 to 1.3 ms on the server (2.3 to
  2.9 ms before), the walk with its layout 0.2 ms.

## No binary releases: the sources, or Docker

- **Gone:** the release workflow (`.github/workflows/release.yml`), `bun run build` (`src/cli/build.ts`), the Lua
  sources carried in an executable (`src/server/luaBundle.ts`) and every branch for running as one (`IS_STANDALONE`,
  the per-user data folder): AddonSim runs from its checkout, which keeps its data (`cache/`, `saved/`, `interface/`).
- **Docker** (`Dockerfile`, `compose.yaml`, `docker/entrypoint.sh`, `.dockerignore`, `docs/docker.md`):
  `docker compose up --build`, then the setup in the page. The image builds the native core (Rust) and LuaJIT 2.1
  from their sources, installs the dependencies and serves the page (published to 127.0.0.1 only); its data (the
  game's files, saved variables, the interface source, the settings) lives in the `/data` volume; a host folder
  (the home by default, `ADDONSIM_FOLDER` for another) is mounted read-only at `/host`, where the page's folder
  browser starts and the setup looks for the game's install. The CLI is in it too (`addonsim test` in a project
  mounted at `/project`; the image is the `addonsim` package a project's config imports). CI builds the image,
  loads LuaJIT and the native core in it and checks that its page answers.
- **The folder browser** (`src/ui/components/FolderBrowser.tsx`, `POST /api/setup/listFolder`,
  `src/server/setup/browse.ts`): Browse… in the setup and the Addons tab's folders opens the page's own browser of the
  folders the server sees, AddOns folders and the game pointed out, the folder looked into checked (its addons, its
  interface source). It replaces the system's folder dialog (`pickFolder.ts`), which no container could open.
- New: `ADDONSIM_HOST` (the address served on; `127.0.0.1` by default), `ADDONSIM_NO_BROWSER=1` (now read: it was
  set by `bun run sim` before but nothing looked at it), `ADDONSIM_BROWSE` (where the browser starts).
