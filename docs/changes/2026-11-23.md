# 2026-11-23: no code of Questie's, releases from GitHub, a boot cache that stays small

## No code of Questie's or QuestieDB's

- `C_EncodingUtil` is AddonSim's own (`lua/encoding.lua`), written from RFC 4648 and RFC 8949: base64 (standard and
  URL-safe), hex (`EncodeHex`, `DecodeHex`, which were missing), CBOR as the client writes it, and compression:
  deflate and zlib through LibDeflate (zlib License, the only vendored code left), gzip with its own header and CRC.
  Its CBOR writes byte for byte what the old copy did; floats read by arithmetic on their bytes, which takes
  QuestieDB's baked data from 8% of the boot to 5%. `lua/tests/encoding.lua` checks it against the RFCs' examples.
- The Questie party member is no longer built in (`lua/questiemember.lua` and `lua/vendor/questie/` are gone): a
  project registers the party addons it needs with its own plugin (WowAddons: `sim/plugins/questie-party.lua`).
  `plugins.gameGlobals()` is new, for a plugin that runs an addon's own code in a sandbox.
- CREDITS.md and `lua/vendor/NOTICE.md` say so: AddonSim carries no GPL code.

## The project

- `.github/workflows/ci.yml`: `bun run check` (types, Biome, `bun test`, the Lua tests) and a build on every push;
  the Lua tests also on Linux arm64 and macOS.
- `.github/workflows/release.yml`: a `v<version>` tag builds the executable for Windows x64, Linux x64 and arm64,
  macOS arm64 and x64, each on its own system, and publishes them with their checksums as the tag's release.
- `bun run build --target=...` names the file for its system (`dist/addonsim-linux-x64`) and sets the Windows
  file details only on a Windows build (a cross build used to fail on them).
- `.gitattributes` (LF everywhere), `.editorconfig`, `bun run check`, `bun run test:lua`, the Bun version in
  `package.json` (`packageManager`, read by CI). The change notes moved to `docs/changes/`.
- The SDK's tests skip themselves on a machine where the simulator is not set up (CI).

## The boot cache

- It never shrank: every changed file left its old entry behind (313 MB, 9600 files here, of which a boot used
  3400). Each boot now lists the entries it used (`cache/boot/*/used/`), and the server deletes, once a day, the
  entries no list from the last two weeks names, and the folders of LuaJIT versions no longer run
  (`src/server/bootCache.ts`).
- Linux and macOS key a file by its write time and size too (through `stat`, checked on a file of its own before
  it is trusted), as Windows did: before, every file was read and hashed at each boot, a third slower.
  `lua/tests/bootcache.lua` checks it on each system in CI.
